# 固定李宁卡片恢复：2026-09-10

## 问题与最小复现

用户在第 813/4349 个关键词遇到新宿主尚未初始化。v8 的 PID + 创建时间守卫正确拒绝旧标记，但缺少普通小店卡片启动步骤，反复重试仍无法恢复。

红测试：`python tools/diagnostics/run_offline_tests.py`，新增 `test_cold_host_gets_normal_shop_bootstrap_before_module_attach` 后首次 198 项中 1 项失败；失败发生在初始化守卫，尚未进入模块校验或 Frida attach。

现场：01:08 主微信与 WMPF 换了进程；旧标记仍指向先前进程。正常打开用户指定的 `lining李宁` 卡片能加载店铺。不能删除安全守卫、伪造初始化标记或仅凭 PID 存在就发送后台命令。

## 排查结果

1. 缺失正常启动入口：已验证。普通卡片加载后可安全创建新的搜索会话。
2. 卡片已定位但点击失败：Qt 将整行消息暴露为一个 ListItem。实际记录为宽 978、高 97；原中心 x=489 是空白，指定卡片位于右侧。改为精确匹配卡片名称后，在自身发送的卡片内容区域按 DPI 定位，当前 x=878。不是固定全屏坐标。
3. 普通首页打开不等于采集调试会话建立：已验证。单纯打开卡片后等 CDP，就绪始终为 False；正常初始化之后还需执行与手动“继续”相同的 guarded attach + LaunchApplet。

中间测试在 02:10:57 发生 WMPF 35560 的 flue.dll 0x19b887b / 0x80000003 崩溃（Windows Application 1000）。该实验曾在挂载后再次打开正常卡片，不能作为发布路径。主微信 49856 未退出。已经删除这条实验路径；最终顺序为：释放旧会话→关闭窗口→正常卡片首页加载→守卫复核→挂载→新搜索会话。

## 实现范围与边界

- `desktop_bootstrap.py`：仅匹配独立 `ChatSingleWindowfilehelper` 窗口内的 `chat_message_list`，并精确匹配 `小店名片lining李宁品牌自营`。不导出聊天树，不读取其他会话，不发送消息。
- 先确认指定卡片可见，再正常关闭小店窗口，确认关闭后才打开；没有杀进程或退出主微信。
- 后台窗口消息不移动真实鼠标、不输入文字；加载成功需要连续三次出现指定店铺名称。
- 新宿主复核 PID 与创建时间、真实店铺窗口，正常入口返回成功也不能绕过守卫。
