## 证据与因果链

1. `tools/diagnostics/cdp-results-before.log`：Runtime.evaluate 的真实返回是
   `id -> result -> result -> value`。此前 evaluate_all 少解一层，成功值被当成 None，
   `exceptionDetails` 也被漏读。使用真实帧编码和消息处理链的回归测试先失败、修复后通过。
2. `cdp-context-inspect.log` 等现场记录：被选中的 AppIndex 是 `page-frame.html` 渲染上下文，
   `getCurrentPages`、`require`、`wx` 全部 undefined。不是“只有 require 相对路径不正确”。
   用户截图中的“搜索脚本无回包，已通过小店可见搜索框输入关键词”说明输入由 UIA 完成。
3. 同一浏览器上下文内的匿名 worker 未提供可用的 Runtime.evaluate 回复；不把换 target 的猜测当成修复。
4. `cdp-native-session.log`：在正常入口打开、钩子安装且调试握手完成后，经已有受保护的
   XWeb.LaunchApplet 注册原生 session，一次真实 XWeb.EvaluateJavaScript 返回
   `pages=function, modules=function, wx=object`。同一时刻的 CDP AppIndex 仍全部 undefined。
5. 因而 `XWeb.version unsupported -> 所有脚本固定走 CDP` 的决策错误：版本信息接口是否支持，
   不能代替页面脚本能力检查。原生 session 没绑定时，模块脚本无从执行；UIA 填词不能恢复商品读取。

用户关于“require 不可用”“UIA 可能掩盖 JS 通道失效”“无客户端立即退出破坏重连等待”成立。
关于只需更换 require 解析路径不成立；本次筛选不是首个故障点，修通逻辑层后真实筛选及分页均成功。
未根据过滤器偏移相差 160 字节就额外改写宿主；本轮未新增过滤器偏移修改。

## 修复边界

- 正确读取 CDP RemoteObject 及异常，不再吞成 None。
- `XWeb.version` 不支持或超时保持能力未知，实际探测页面/模块/wx。
- 首次绑定失败只在宿主调试就绪后调用既有受保护的原生注册；注册后有界轮询验证，
  轮询不重复 LaunchApplet。未初始化或取消时不发送原生启动。
- 搜索前确认逻辑层可用，原生同步调用读取状态；长分页仍使用既有异步 job + 短轮询，
  不恢复 5 秒内等待整个 CGI 的旧做法。
- 恢复 CDP 无客户端期间的有界等待和取消。
- 对本地上下文/模块、搜索及筛选未就绪使用类型化恢复错误，保留页错误包装的类型。
  安全验证仍不归类为自动恢复；明确接口不存在也不伪装无商品。
- 移除“可见窗口 + 状态读取失败也算搜索页就绪”的假成功；暂停清除就绪缓存，继续时重新核验。
- 保留主图明确字段选择、增量落盘、去重及读到服务端末页的逻辑，没有关键词页数上限。
