# v12：恢复入口缺失导致三次暂停

## 证据与范围

用户截图停在第 1888/4349 个关键词“卡通母婴床盖套件”，小程序 PID 65260 process-terminated；之后错误为“普通小店卡片自动打开失败：自动打开入口不可用”，最终消耗三次关键词重试并暂停。只读进程路径核对确认本机运行的是 v10（PID 51948），不是上一轮发布的 v11。

该文本精确对应 `_ShopUI.require_card` 的“未识别到唯一独立文件传输助手窗口”分支，不是商品不存在，也不是已定位卡片后的点击错误。用户不确定当时是否有独立窗口。本轮无法使用原生桌面观察工具确认窗口真实状态，未使用自建 GUI 脚本绕过工具限制。因此不能断言窗口被用户关闭，或确定最小化就是现场根因。

## 红测试与假设

`python -m unittest discover -s tests -p test_desktop_entry_recovery.py -v` 首次测试 FAIL，重现真实 UI 查询错误 → FileHelperShopOpener → Backend 正常恢复 → Listener，输出与截图相同的“三次重试后暂停”。最小场景是前四次入口查询缺失，第五次可用；旧实现第四次就结束，无法自动等到第五次。

已向用户给出排序假设：入口异常分类错误；窗口最小化/隐藏识别失败；指定卡片滚出可见区域。第一项通过实际调用链回放证实。后二项是模拟暴露的兼容缺口，不能当作已确认的现场状态。

## 修改

- 入口不可用使用 `ShopBootstrapEntryUnavailable` → `DesktopRecoveryEntryUnavailable` 明确类型传递，避免字符串混入关键词失败。
- 缺少入口进入独立、可取消的自动等待，15/30/60/120 秒封顶；不写完成断点，不消耗关键词失败次数。入口再次可用即正常开店、返回搜索页、继续同词。
- 开始采集前先检查该恢复入口，不关闭/打开小程序、不挂载 native；缺失则立即显示等待状态。
- 已匹配进程、独立窗口标题和 AutomationId 后，才尝试显示隐藏/最小化窗口；不激活、不移动鼠标。
- 只对指定卡片精确查询并使用 ScrollItemPattern；请求滚动不等于成功，重新查询到可见卡片才能继续。接口不支持则等待，不使用猜测坐标点击。
- 关闭旧小程序前仍需确认指定卡片；身份变化、多窗口歧义、取消均不能继续点击。
- GUI 显示真实的恢复等待状态；入口可用后的流程仍遵守宿主初始化、版本校验、真实搜索页稳定检查。

API 依据：[ShowWindow / SW_SHOWNOACTIVATE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow)、[ScrollIntoView](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationscrollitempattern-scrollintoview)。接口存在不代表当前微信一定实现 ScrollItemPattern；代码保留失败等待分支。

## 边界与验证

独立窗口已被彻底关闭、指定卡片删除或不在加载的 UI 树中时，目前不能自动从微信主窗口创建入口。需要用户重新单独打开文件传输助手并让卡片可用，随后自动继续。不能将持续等待包装成已完成完全无人值守启动。

没有操作鼠标、打开聊天、退出微信、改写正式数据或替换运行中的旧采集器。新动作只有离线模拟验证，真实目标窗口复测仍待进行。

离线 runner 将 `_ShopUI.__init__` 禁用，允许用 `__new__` 加完全模拟的 UIA/Win32 对象测试真实查询方法，同时禁止构造真正 UI 客户端；Frida attach/spawn 仍完全禁用。
