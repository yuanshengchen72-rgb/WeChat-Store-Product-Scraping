# v5 停止后重开失败与本轮卡死记录

## 状态

v6 源码、178 项离线测试、最终代码的受控实机验证和完整包自检已通过。停止后重开、单次超时自动恢复、完成当前词后的定时重开均已实测；两个原进程在测试退出后 60 秒仍存活且响应。未进行数千词长跑，不能宣称所有微信卡死都已解决。旧 v5 压缩包仍含此次已复现的恢复缺陷，不应继续分发。

## 可重复的失败路径

用户截图：第 123/4349 个关键词“小清新保暖四件套”，停止后再次开始，XWeb 失败转 CDP，随后显示“电脑版微信页面脚本执行失败：RuntimeError”，60 秒后重试。

修改前运行：

```text
python -m unittest discover -s tests -p test_desktop_resume_failure.py -v
Ran 3 tests in 0.002s
FAILED (failures=3)
REPRO_PAGE_FAILURE: 电脑版微信页面脚本执行失败：RuntimeError
```

测试通过实际 `DesktopWechatBackend.evaluate → WmpfCdpBridge.evaluate_all` 包装链，并在协议调用边界注入无消息的 FutureTimeoutError。另用真实 Future/线程在停止时取消等待，观察是否继续向第二个页面发送命令。

按优先级核对的环节：

1. 超时类型被丢弃：`RuntimeError(str(TimeoutError()))` 变为空文本；关键词重试器不把它判为可恢复连接故障。测试复现该错误，并证明原逻辑没有调用恢复分支。
2. 停止后的任务泄漏：取消第一个 context 的等待后，`evaluate_all` 捕获异常并向下一个 context 发命令。测试修改前发出两条，修改后只发一条。
3. 旧页面状态被复用：停止只保留连接，没有要求重新开始验证新的小程序页面；旧 socket 也未区分消息来源。新增对应回归测试。

以上证明软件恢复链有缺陷；不等于已证明真实微信线程为何首次停止响应。

## 源码修改

- 保留带命令、页面和等待时间的超时类型，避免空 RuntimeError。
- 取消以代次隔离：旧调用不得继续发送或返回结果；旧 socket 不能修改新页面状态。
- 停止后再次开始以及连接故障恢复，都关闭小程序并废弃旧调试页面；重新打开后要求新连接代次就绪，才验证搜索页并继续。保留微信登录及原生连接，不结束微信进程。
- 可恢复连接失败使用至多 2 秒等待后重开当前词，而非每次等待 60 秒；最多重试 3 次，失败保留断点，不伪造成功。
- 定时重进仍使用已有可输入间隔，0 为关闭。等当前词实际末页完成后再完整重开小程序，不截断当前词。
- 无结果、需要登录、安全验证不被当作可无限重试的连接失败。

## 测试隔离事故与实时证据

本轮修改启动代码后，第一次运行旧完整测试集时，`test_cold_launch_uses_supported_parameters_and_waits_for_runtime` 只替换了同步 `call`，没有替换新增异步 `dispatch_async` 分支，误进入真实 backend 的启动/挂载路径。错误输出中 captured method 为 `XWeb.version`，不是 LaunchApplet。该用例现已隔离异步调用。

随后用户报告小店和微信卡死。2026-09-09 12:12 的只读检查显示：微信主进程 PID 41200 与小程序宿主 PID 29712 均仍存活，但 `Responding=False`；最近 25 分钟未查到匹配的新 Application 1000/1001/1002 事件。其后再次检查仍未响应。当前私人内存分别约 474 MB、215.7 MB；这些数字不能证明是内存累积导致的卡顿。

不能排除误挂载/启动叠加用户正在运行的 v5 导致本次挂起，已向用户明确说明测试隔离失误。没有原生线程堆栈，不能归因到特定 native 锁或单一函数。未强杀、重启微信，也未替换正在运行的 v5。

增加 `tools/diagnostics/run_offline_tests.py`，在整套测试执行期间禁止 `frida.core.Device.attach` 与 `spawn`，避免普通回归测试再次接触真实目标。修改后通过该入口运行：

```text
python tools/diagnostics/run_offline_tests.py
Ran 178 tests in 3.212s
OK
```

下一步需要先停止用户的采集软件并恢复卡死的微信，再单独、明确授权进行受控实机验证。小程序正常关闭命令依赖微信仍可响应；主微信一起卡死时，仅重开小程序不能保证恢复。没有通过实机前不发布稳定版或声称“彻底解决”。
