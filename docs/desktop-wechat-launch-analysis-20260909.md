# 电脑版微信小店无法首次唤起：参考软件核对记录

## 结论

当前故障发生在创建小程序宿主进程（WeChatAppEx.exe / WMPF）之前，而不是关键词输入、搜索结果加载或微信登录阶段。微信主进程存在且接收了启动链接，但小店 AppID 没有通过当前版本的链接启动检查，因此没有创建小程序宿主。

参考软件的成功日志证明其内部搜索链路在已有 WMPF 宿主的情况下有效，不能作为无宿主冷启动成功的证据。本次尚未成功打开用户要求的搜索窗口。

## 参考软件当前关键词链路

`App._get_kernel_connection()`：

1. 可复用的共享连接存在时直接返回。
2. 创建 `WechatXwebBackend`，调用 `start()`。
3. 打开软件配置的引导店铺。
4. 后续通过 `open_search_page()` 转到 `globalSearch` 搜索页。

`WechatXwebBackend.start()`：

1. 查找微信进程与线程。
2. 查找已经存在的 WMPF 根进程，允许复用带 `--web-translate` 的宿主。
3. 只有找不到宿主时，调用 `_launch_wmpf_host()`。
4. 找到宿主后，读取微信/小程序模块版本、挂载内部接口、建立本机调试桥。

`_launch_wmpf_host()` 实际使用：

```text
weixin://launchapplet/?app_id=wxca8d4b8e8feedc2a
```

它调用 Windows 已注册的微信协议，然后等待 WMPF 出现；这里没有另一个已实现的冷启动补救分支。后台 `XWeb.LaunchApplet` 调用在宿主存在并挂载以后才进行。

原始 `logs\collector-20260908.log`：

- 第 86 行，14:49:30：随后通过 `XWeb.LaunchApplet` 打开引导店铺页面。
- 第 107 行，14:49:33：内部启动命令返回成功。
- 第 119 行：调试运行环境准备完成。

日志中较早的“正在让微信后台启动”是上层状态文案；判定是否实际发生了冷启动，应以第 71 行的进程状态和真实分支为准。

## 当前机器的实际复现

- 微信主进程 PID 9104 持续存在。
- 启动请求之前，没有 WeChatAppEx.exe。
- Windows ShellExecute 返回 42，只表示协议处理程序被调度，不能表示小程序已经打开。
- 在当前 Weixin.dll 中只跟踪本次启动请求：微信收到该 URI，并进入 applet 启动处理函数。
- 增加参数分隔符的验证请求解析出的 AppID 仍为正确的 `wxca8d4b8e8feedc2a`。
- AppID 对应的链接启动检查返回 false，启动处理函数返回 false，随后没有宿主进程出现。
- 未修改该检查的返回值、未修改微信文件、未重启或退出微信。
- 参考软件另有 `ShopLinkCandidate.launch_uri` 短链接属性；直接调度其引导店铺的 business URI，本机同样没有创建宿主。不能把该属性本身当成已经验证成功的冷启动方案。

## 参考软件另一个流程与权限边界

`Collector._launch_shop_link()` 是独立的旧店铺链接流程：确认文件传输助手 → 发送完整店铺短链接 → 点击刚发送的链接 → 等待新小店窗口。它不是上述成功关键词日志使用的分支，也不等同于对短链接调用 ShellExecute。

这一原生聊天链接流程可以作为下一步待验证的冷启动候选，但会增加向用户自己的文件传输助手发送消息的动作。本次没有执行消息发送，也没有启动参考软件的采集。

## 对本项目的影响

本项目 `wechat_shop_scraper/desktop_keyword.py` 的 `_launch_wmpf_host()` 依赖同一普通 AppID 协议。当前“电脑版微信小程序进程未启动，请确认微信已经登录”的错误把宿主启动失败误导为登录问题。

需要分别处理：

1. 微信主进程不存在。
2. 微信进程存在，但小程序宿主不存在且唤起失败。
3. 宿主已存在，但内部接口/调试通道不就绪。
4. 内部接口可用，但搜索页面没有打开。

下一步必须验证真正可用的宿主冷启动途径，然后才接入已验证的内部搜索页链路。不能用延长等待、重复相同链接、假定微信未登录，或者仅通过模拟测试来宣称修复成功。
