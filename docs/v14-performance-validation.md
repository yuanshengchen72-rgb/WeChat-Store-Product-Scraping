范围：用户确认前两项优化。未修改搜索/筛选等待、失败恢复时序、请求并发、完整分页规则、每 30 词重启设置。没有连接真实微信或操作当前采集进程，没有读取/写入正式批次做测速。

## 实现

- `IncrementalProductStore` 使用同步提交的 SQLite 待合并记录，按商品 ID 保存完整合并后状态。提交成功后才发布到内存，GUI 随后才允许推进关键词断点。
- 正式数据仍输出兼容的 JSON 和每 1000 行一卷的 CSV。GUI 每 15 秒在独立工作线程导出；每页不再全量导出。快照导出期间的较新提交不会被删除。
- 停止时加入事件队列屏障，先处理已收到的页面再做最终导出，结束后才允许再次开始。关闭时同样排空存储事件。保存失败不推进断点或声称完成。
- 分页就绪的轮询在返回结果时同时删除异步任务；少一次清理 RPC。异常路径仍清理，未完成任务保留，原 60 秒任务清理兜底不变。
