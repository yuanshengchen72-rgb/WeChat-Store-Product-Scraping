# v8：空白小程序经普通店铺首页自动恢复

## 用户现场与范围

用户报告 v7 再次空白，关闭提示和小程序、正常打开店铺首页、继续采集即可恢复，要求自动执行同样的恢复流程。

只读日志确认 16:57 第 430/4349 个词“母婴加厚保暖棉被芯”第 16 页读取超时；16:58–17:00 三次直接启动搜索页均收到 LaunchApplet 回包，但没有新的初始化，连接代次一直为 7、页面数为 0。17:01 用户手动操作后连接代次增长、初始化成功；该词最终 18 页 171 商品，后续继续采集。可证实的是“仅收到启动回复不足以恢复页面”以及旧恢复分支没有经过店铺首页；不能据日志断言所有空白的底层原因相同。

用户确认“已关闭”采集器后才做后台实机测试；没有操作鼠标键盘、没有退出微信登录，没有运行参考软件。普通店铺路由及数据契约仅静态核对既有提取字节码，并以本机返回值再次验证。

## 反馈循环

命令：`python tools/diagnostics/run_offline_tests.py`。测试入口屏蔽真实 Frida attach/spawn。

新增测试先复现：搜索页未就绪时应进入首页恢复；首页恢复失败不能假报搜索可用。187 项测试中 1 错误、1 失败，原代码直接抛“采集通道未就绪”。实现后通过。

向用户说明的排名假设：缺少首页初始化、残留旧小程序会话、宿主更换。测试先改变启动路由，沿用正常关闭/启动命令，不通过杀进程或移除原生保护扩大改动。

## 实现

- 从已经成功读取的商品页记录最多 3 家真实店铺的公开 AppID；严格校验格式、排除小店容器 AppID、去重。只保存 AppID 和店名，不保存会话、登录凭据或页游标。缓存原子替换，不写入商品表或关键词断点。
- `open_search_page` 发生可恢复的启动/导航错误后，执行关闭小程序、打开已记录的普通店铺首页、核对实际 AppID 和已加载 tabs、再导航到关键词搜索页。
- 不依赖固定店铺。每次首页恢复最多遍历 3 个已记录入口，仍失败交回原有有限重试/暂停流程。没有入口时明确提示，不猜店铺、不发送聊天消息。
- 登录失效、安全验证、频繁访问提示不触发换店绕过；停止期间禁止继续打开首页或继续读取。
- 首页商品不进入采集回调；恢复后原关键词从第一页重新读取并沿用去重，只在该词实际末页返回后更新断点。定时重开、价格筛选及每 1000 条 CSV 规则不变。

## 实机发现并追加修复

第一轮首页启动和通道都成功，但首页就绪检查未通过。第二次只验证一个入口，捕获实际状态：

```json
{"route":"subpackages/shopWindow/pages/wxShopHomeLite/index","appid":"wx677b05c4ba7096ed","ready":true}
```

微信将普通首页重定向到轻量首页，原候选代码只接受 wxShopHome。先用真实状态新增失败回归，再增加 wxShopHomeLite 白名单；仍要求实际店铺 AppID 匹配且 tabs 已加载。

17:17–17:18 的完整恢复测试成功，随后观察到首页导航搜索时会更换调试连接，第一次 route 成功后短暂离线可能引发不必要的再次 LaunchApplet。新增连接更换时序回归，旧实现失败；加入 `_wait_search_handover`：在相同连接代次上连续三次确认搜索路由和真实 runtime_ready，中途断开或换代重新计数，不另开小程序。

最终 197 项测试全部通过（3.346 秒）。诊断脚本放在 `tools/diagnostics`，正式代码无 DEBUG 临时探针。

## 最终真实验证（17:20:24–17:21:36）

脚本：`python tools/diagnostics/desktop_home_recovery_probe.py`。

1. 对原失败词读取到实际末页：18 页、171 商品，自动取得 3 个可用店铺入口。
2. 在真实搜索页启动路径注入一次“通道未就绪”结果，触发正式代码的首页恢复分支。
3. 实际执行 CloseApplet → LaunchApplet 店铺首页，核对首页身份与内容 → 导航搜索 → 等待连接换代稳定。不是模拟首页内容，也不是仅验证发出了命令。
4. 从搜索页重采相同词，再次到末页：18 页、171 商品；连接切换期间没有额外 LaunchApplet。
5. 正常释放控制器；主微信 PID 46360、小程序宿主 PID 29244 仍响应，17:12 起未发现匹配的 Application 1000/1001/1002 新崩溃记录。

故障触发是注入的未就绪信号；用户原有自然空白当时已手动恢复，未宣称完整复现其底层原生故障。验证证明新增恢复流程真实可执行，不代表所有微信故障均可恢复。
